# Exam Service

REST-сервис для проведения экзаменов: преподаватель составляет экзамен из заданий и публикует его, студенты проходят попытки и отвечают на задания, сервис сам проверяет ответы и выставляет итог.

## Сущности

| Сущность | Таблица | Описание |
|---|---|---|
| User | `users` | Студент |
| Exam | `exams` | Экзамен: название, проходной балл, лимит времени, статус `DRAFT → PUBLISHED → ARCHIVED` |
| ExamTask | `exam_tasks` | Задание экзамена с эталонным ответом и максимальным баллом |
| ExamAttempt | `exam_attempts` | Попытка студента: `IN_PROGRESS → PASSED / FAILED` |
| TaskSolution | `task_solutions` | Ответ студента на задание в рамках попытки и начисленный балл |

Связи: Exam 1–N ExamTask, Exam 1–N ExamAttempt, User 1–N ExamAttempt, ExamAttempt 1–N TaskSolution, ExamTask 1–N TaskSolution.

## Ограничения целостности в БД

- внешние ключи с `ON DELETE CASCADE`;
- `username` и `email` уникальны;
- баллы и лимиты неотрицательны, статусы только из допустимого набора;
- у попытки `end_time` заполнен тогда и только тогда, когда она завершена;
- у студента не более одной активной попытки на экзамен (частичный уникальный индекс);
- на одно задание в попытке не более одного ответа (`UNIQUE (attempt_id, task_id)`).

## Бизнес-операции

| Операция | Запрос | Правила |
|---|---|---|
| Опубликовать экзамен | `POST /api/exams/{id}/publish` | только из `DRAFT`; есть хотя бы одно задание; проходной балл достижим |
| Архивировать экзамен | `POST /api/exams/{id}/archive` | только из `PUBLISHED`; нет активных попыток |
| Начать попытку | `POST /api/exam-attempts` `{examId, studentId}` | экзамен опубликован; у студента нет активной попытки |
| Ответить на задание | `POST /api/exam-attempts/{id}/answers` `{taskId, answer}` | попытка активна; время не истекло; задание из этого экзамена; повторный ответ заменяет старый; балл считает сервер |
| Завершить попытку | `POST /api/exam-attempts/{id}/finish` | попытка активна; сумма баллов сравнивается с проходным → `PASSED` или `FAILED` |

Дополнительно: экзамен и его задания можно редактировать только в статусе `DRAFT`, решения нельзя менять и удалять после завершения попытки. Операции выполняются в транзакциях с блокировкой строки экзамена или попытки.

## CRUD

`/api/users`, `/api/exams`, `/api/exam-tasks`, `/api/task-solutions` — `GET`, `GET /{id}`, `POST`, `PATCH /{id}`, `DELETE /{id}`.
`/api/exam-attempts` — `GET`, `GET /{id}`, `POST`, `DELETE /{id}`; состояние попытки меняется только бизнес-операциями.

Ошибки: `404` — объект не найден, `400` — нарушено бизнес-правило, `409` — нарушено ограничение БД.

## Запуск

```bash
cp .env.example .env
docker compose up -d
./mvnw spring-boot:run
```

При первом старте контейнер создаёт таблицы (`db/01-schema.sql`), тестовые данные (`db/02-data.sql`) и пользователя `DB_USER` только с правами `SELECT/INSERT/UPDATE/DELETE` (`db/03-app-user.sh`). Приложение подключается под этим пользователем. Чтобы пересоздать БД: `docker compose down -v`.

Сценарий запросов — `requests.http` (IntelliJ IDEA HTTP Client), выполнять сверху вниз.
